# Workshop Paper Submission

Production backend deployed on 2026-11-12 as Apps Script version 113. The confirmed 21-team roster and separate test roster are configured. A controlled system-test PDF was stored in the private test folder; its notification and exact-size PDF attachment were verified in the organizer's Gmail inbox and Sent folder. No participant submission was generated by this test.

## Participant Flow

- `/finals/` keeps the finalist form. Non-finalists see the same heading, layout and button styles, with an invitation to submit a preliminary technical report.
- `/#/workshop` links to `/#/workshop/submit`.
- The paper page offers the supplied, unchanged template ZIP and registered-email/token login. Sessions from the finals page are accepted.
- After login, **Submit a paper** opens the native file picker and uploads the selected PDF. Limit: 10 MiB. The backend checks size, PDF header/end marker and SHA-256; this is not a full PDF parser or page-count check.
- The confirmed finalist roster determines the `finals` category. Other active registered users submit to `preliminary`. The browser cannot override team, stage, recipient or destination folder.
- Requests are stored separately in `PaperSubmissions`, not preliminary/finals evaluation records. Users can see only their own receipts.
- Identical bytes from the same account/stage reuse one receipt, file and email. Different bytes create a new version; earlier PDFs are not overwritten or deleted.

## Storage And Mail

Private Drive root: `RoboSynChallenge2026_private/technical_reports/`, separate from the shared evidence tree. Tests use the sibling `technical_reports_test/` folder.

```text
technical_reports/
  preliminary/{team_id}/preliminary_{team_name}_{paper_id}.pdf
  finals/{team_id}/finals_{team_name}_{paper_id}.pdf
```

The root is selected using its Drive ID, not a folder-name search. Only organizers should have access to the root and ancestors. No public links or participant editing permissions are created. Link-wide/public/domain sharing is rejected; named-user and inherited access must also be checked when choosing the root. Test accounts require a different root and never send email. Only the authenticated organizer-only `paper_admin_smoke` action can explicitly send a system-test notification; its stable probe ID prevents duplicate delivery.

Notifications go only to `robosynchallenge@gmail.com`, using the existing Gmail API authorization. The MIME message includes the exact uploaded PDF as an attachment, the participant's email in Reply-To, stage, receipt, SHA-256 and private Drive link. This does not call MailApp, but Gmail API/account limits still apply. See [Gmail sending documentation](https://developers.google.com/workspace/gmail/api/guides/sending).

Drive persistence precedes notification. A known mail rejection leaves the PDF stored and notification `pending`. An uncertain send is `delivery_unknown` (or `sending` after a process interruption), and is never automatically resent. Inspect Sent using `rfc822msgid:{paper_id}@robosyn-bench.net` before resolving such a record. Do not mark it pending unless non-delivery is confirmed.

## Production Configuration

Deploy the new `PaperSubmissions.gs`, the `paper_*` dispatcher in `Code.gs`, and the finals identity helper in `Finals.gs`, preserving unrelated remote changes. Publish the frontend assets and `material/RoboSynChallenge-2026-submission-template.zip` together. Existing Drive and Gmail OAuth scopes are already in the manifest.

Set Apps Script properties:

| Property | Value |
| --- | --- |
| `PAPER_DRIVE_ROOT_ID` | Private organizer-only technical-report folder ID |
| `PAPER_TEST_DRIVE_ROOT_ID` | Separate private test folder ID |
| `PAPER_INTAKE_ENABLED` | `true` only after configuration and a controlled live test |
| `PAPER_DEADLINE_AT` | `2026-11-16T12:00:00Z` exclusive cutoff, equivalent to November 15 at 23:59 AoE |
| `FINALS_ROSTER_JSON` | Existing confirmed finalist roster |
| `FINALS_TEST_ROSTER_JSON` | Separate test roster |

The organizer-only `paper_admin_configure` action initializes private storage and installs a 10-minute time trigger for `retryPaperNotifications` idempotently. The trigger retries up to five pending notifications per run, with at most five delivery attempts per report, and skips uncertain sends. An incomplete Drive write can be retried by selecting the same PDF. Deterministic file naming recovers a completed Drive write if its sheet receipt was lost.

Before opening production intake, test a small PDF with the test roster/root, then one explicitly approved formal upload to verify permissions, Apps Script request size, actual Drive ownership and Gmail attachment delivery. Unit/local tests do not prove these live account settings.
